# 写入与核验

入口 `python3 bin/broll.py`，只连接用户已打开的工程；不切数据库、不换工程。未指定 `--timeline` 用当前时间线。此发布版通过 Resolve SDK（达芬奇程序接口）直连读写，保存、关闭、重开同一工程并读回；这是 b-roll/fx 的正式写入与核验方式；不沿用旧 A-roll 的 MCP 交付步骤。时间线只支持29.97 fps。

## 开始前

`status` 确认工程、时间线、数据库和工作目录。每条命令自动检查 UTF-8、ffmpeg 架构/zscale、NAS、SDK与数据库。项目目录由 V1源路径推出；不能唯一推出时问一次项目位置，再用 `--project-dir '<项目目录>'`，后续命令沿用。已有 `<项目>/B-roll_AI/` 继续使用；新项目有 `3.视频素材/3.7AI素材/`（或 `3.7 AI素材/`）时用其下 `B-roll_AI/<片名>/`（片名默认取项目文件夹名），否则保持旧默认。不搬迁旧目录，不写共享程序目录。

默认配置 `~/.config/ai-talking-head-edit/broll.json`，可用 `--config '<配置文件>'` 指定已有配置。PostgreSQL协同库在测试工程实机通过前拒绝写入，`allow_postgres_apply` 默认false；不能为绕过报错自行设true。已有实测证据且获授权后才放开，未知数据库始终停止。本说明与离线测试都不是实机通过证据。

## 原素材直接写入（优先规则）

优先复用媒体池原文件夹里已有的 MediaPoolItem，直接放到时间线并裁切源入出点；未导入的素材才从原路径导入。写入前后核对原文件名、媒体池名称、时间线名称和实际源路径，不改名、不复制改名、不渲染替代视频来完成普通 B-roll 插入。描述与运行编号只写备注或台账。

`apply/adjust` 已按此规则使用原素材：照片直接放置，恒定29.97 fps普通视频直接引用，池外普通素材先从原路径导入。HDR、可变/未知帧率及暂不支持直接放置的源帧率走转换；衍生文件名包含原文件名，台账的 `source_file`、`source_start`、`derivative_reason` 记录来源与原因。媒体池已有 Input LUT 的普通原片沿用该 LUT；池外 Log 必须有可解析的文件夹 LUT，否则跳过。照片直接放置后若长度不符，先核对它确为本次新增且其他片段零变化，只删除这一片段，再生成文件名含原文件名的衍生片段继续写入，台账 `derivative_reason` 记录请求与实际帧数；同次运行后续照片直接生成衍生片段并在清单说明。其余异常仍补偿并停止；源帧域、名称持久化及此回退仍待实机确认。

## 演练与写入

1. `plan`、看图补描述并填匹配（见[看图与匹配](看图与匹配.md)）；素材多时先报每10段约2分钟。不要让用户写JSON或运行命令。
2. `apply --matches '<匹配文件>'` 默认演练；确需转换时才生成本地衍生片段，尚未写时间线。必须打开输出的 `演练核图/<run>.jpg`，逐镜核对实际源入点、中点和出点（照片一帧）；再检查演练的点位、轨道、素材、原声与跳过原因，确实需要写入才加 `--apply`。
3. `adjust`、`undo` 同样默认演练，写入须加 `--apply`。配 B-roll和明确局部调整已授权对应主线改动，无需再问同一权限；范围扩大或碰到手改保护时停下问一句。
4. 本机锁 `~/.cache/ai-talking-head-edit/resolve-write.lock` 用 `flock` 排他写入；提示“请暂停操作达芬奇约30秒”。不要手动删锁文件，进程退出释放锁；索引还有独立锁。

## 只动自己的片段

首次命令登记旧 AI 片段，之后由台账认领。名字/路径/颜色不单独当身份凭证。主线不加 AI 标记，新插入保留原素材名称，不加 `[B-…]` 前缀；AI 归属通过台账中的片段 ID、原素材 ID、路径、源入出点与时间线位置核对。Teal颜色只作视觉提示。备选仅存台账，不建备选视频轨；默认不放原声。

每处写前重读快照，必须与计划依据一致。删除/替换前精确比较原存档：起止、源入点、启用、名称、颜色、音量与全部变换属性，任何差异都视为她动过，拒绝删除或覆盖。不能把自动学习后的新状态当作已授权删除基线。点名父编号会处理同一语义段的子镜头，其他位置不动。

替换/删除先在媒体池 `B-roll/历史` 保存时间线副本，再保存旧片段参数、非波纹删除、放新片段并读回；失败按参数补偿旧片段并停止。整次失败尝试回滚；只有恢复后保存、重开、读回通过，才能说“时间线已恢复原样”。回滚未核验时说明缺口，请用户暂停操作以保留现场；没有自动DRT破坏性恢复。

开原声只针对那一处，放到“B-roll 原声”音频轨（缺轨才建）、−5dB并链接，保存重开核对；照片/无声片段不能开声音。

## 完成条件与撤销

整次核对除登记增删外，原片段、轨道与标记零变化；保存重开后再次核对，检查本次1–3帧闪缝与原声链接，再写台账。仅点击保存或返回成功不算交付。

首次整片配完在原主线看；局部修改另建 `B-roll审核_<主线>_<运行编号>` 放 `B-roll/审核`，标记仅在审核线。`at --playhead` / `at HH:MM:SS:FF` 可把审核线位置映回主线；请用户回原主线修改。

`undo --apply` 撤销最近未撤销运行，或 `undo --run '<运行编号>' --apply` 撤销指定运行：只删该次写入且未手改的片段，恢复该次删掉的旧片段并核验。后续已改同一位置须先撤销后续；手改片段仍拒绝删除。成功的历史/审核副本保留供对比。

旧流程的生成片段在 `B-roll_AI/B-roll片段/`；新插入优先引用原素材，仅需转换或照片长度回退时新增衍生文件。`clean` 检查全工程媒体池及全部时间线引用，只把未引用的MOV/WAV及JSON移到 `B-roll片段/待清理/`；实际删除须用户明确同意后才 `clean --yes`，仍被引用的一律不动。
