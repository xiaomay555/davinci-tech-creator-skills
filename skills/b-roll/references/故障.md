# 出错后由 Codex 做下一步

先给中文原因，再说接下来处理什么；需要用户回答时一次只问一个问题，不让她照命令操作。失败返回码2；不要原样抛出英文报错，也不要反复重试尚未核验的写入。

| 报错或现象 | 下一步（Codex执行，或只问必要的一件事） |
|---|---|
| 找不到ffmpeg、架构不符、缺zscale | 核对本机接入与可用的ffmpeg，必要时按工作台接入流程修复，再重试；不要求她敲命令 |
| Python未开启UTF-8 | 使用入口 `python3 bin/broll.py` 的自动重启；仍失败时检查启动环境 |
| NAS未挂载、学习路径未配置 | 检查挂载与现有配置中的 `nas_mount`、`learning_root`、`ledger_index`；不在缺失卷上新建假目录冒充已挂载 |
| 达芬奇未连接、工程或时间线没打开 | 确认SDK连接；确实没开时请她先打开要做的工程/主线 |
| 发布版只支持29.97时间线 | 说明这条时间线目前不支持，停止写入；不擅自改帧率 |
| 数据库未知、PostgreSQL默认拒绝写入 | 核对库类型和实机验收记录；协同库未验收先保持禁写，不开开关绕过 |
| 推不出项目目录、创作者未配置 | 只问一个缺项，得到回答后由Codex补 `--project-dir` 或 `--creator` |
| 台账不属于当前工程或数据库、口播源改变 | 核对所选主线；来源变了用新项目，不覆盖旧基线 |
| 同谱系两条线都改过、线名变了 | 问学哪条，用 `--timeline '准确线名'`；不替她选 |
| 历史/审核/逐句否决线默认不学 | 回原主线；指认审核位置用 `at` 映射，不在审核副本写入 |
| 字幕与V1不同步、口播源映射不连续 | 停止学习，检查口播和字幕；不能猜时间戳 |
| 身份不确定、超过20% | 保留现场和旧档案，核对台账与素材证据，不猜归属 |
| 前三候选缺质量字段 | 打开生成的 `补充描述/补充描述.json` 中图片，填补充列表，运行 `plan --supplements '<补充文件>'` 再试 |
| 匹配字段/行范围/候选不存在 | 对照最新 `B-roll匹配稿.json` 修正JSON，逐张看图；不编造编号或行号 |
| 匹配稿依据变化、写入间哈希不符 | 停下，重读当前主线并重新 `plan`、匹配；不沿用旧行号 |
| 覆盖率下降超过15个百分点 | 说明变化，问是否接受；明确同意后只对本次设 `coverage_confirmed=true` |
| 片段被手动修改，拒绝删除或覆盖 | 告诉她哪处受保护；保留手改，讨论点名范围内的处理，不自行重置保护基线 |
| 没有备选、没有可调整片段 | 查台账；有别的已描述候选可用 `adjust --spot <编号> --segment <素材段ID> --apply`，无可用项就说明缺口 |
| 无原声 | 说明这段素材没有声音，不伪造音轨 |
| Log没有LUT、LUT缺失或同名不唯一 | 核对来源色彩转换；该候选跳过并尝试其他素材，全部不可用就留口播，不出灰片 |
| 目标轨停用/不再可用、用户画面或保留位、闪缝 | 重新读取并排布；仍不满足就跳过，不新建视频轨或覆盖她的画面 |
| 另一处正在写达芬奇或建索引 | 等正在执行的进程结束再试，不删锁文件 |
| 后续运行改过同一位置 | 先查后续记录，按用户撤销范围从后向前撤销，不扩大范围 |
| 没有可撤销运行/没有可忽略学习 | 如实说明目前没有可撤销内容，不编造成功 |
| 写入失败，已恢复原样 | 只有程序明确保存重开核验通过才转述恢复成功，说明原失败原因后修正 |
| 自动回滚未核验/原声链接丢失/重开读回不符 | 立即停止，请她暂停达芬奇；检查现场及历史副本，说明未核验的具体内容，不报告完成 |

汇报句式：“出错了：这处片段被你改过，程序保护它，停止了替换。下一步：我先核对这处现状，再确认要怎样处理。”只有确实读回的状态才当事实。
