# 花字音效

## 用户手工定稿保护（所有工程、所有 Skill，2026-10-17）

**用户原话：“只要是我改过的素材都不要再改了。”用户手动制作或修改后的版本就是最终素材。**

- 适用于所有工程与所有制作 Skill，包括 A-roll、B-roll、字幕、花字、音效、图片、窗口、Fusion 节点及其参数。手动改过的整个素材／片段从批量修改、统一样式、重建、替换、清理和重新交付中排除，不能只保留几个改过的字段再重建它。
- 每次写入前以当前工程为准，对照上次 AI 写入记录辨认手改，并按片段 ID、源素材和当前范围记录保护清单。原本由 AI 创建也不代表可以继续接管；没有可靠基准或不能确定是否手改时，保留现状，不覆盖。
- 手工参考只供只读学习；不能修改参考本身，也不能用旧计划、默认参数或统一模板把手改版恢复成 AI 旧版。用户删除、替换、停用或拆掉的内容不得自动补回。
- 只有用户明确点名该对象并要求再次修改时，才调整其点名的内容，其他部分仍保留。“全片统一”“全部重做”“按这个模板”本身不授权覆盖手工定稿素材。
- 工具若不能排除受保护对象，就改用只处理已授权目标的局部方式；做不到则跳过该项，不能先整批覆盖再补回。写后核对保护对象没有变化；发现误改只撤销本轮造成的变化，不拿旧快照覆盖用户新改动。

制作 使用者 的流程／说明动画、动画字卡或用户说“按之前动画的颜色”时，先读 [动画默认配色](references/动画配色.md)，沿用 2026-10-17 确认的灰蓝 v5；这只定义动画配色，不覆盖口播白字或玻璃花字。

**“口播花字”固定调用（2026-10-17 使用者 确认）**：先读 [口播花字](references/口播花字.md)。采用本次确认的寒蝉端黑体白字及 Text+ 原生着色阴影，只开启或复用确认模板，保留全部参数；不用其他阴影方案。此命名定义优先于旧案例与历史参数；章节、玻璃底板及 B-roll 指定配色仍各自处理。

用户说“玻璃花字”“左侧双条玻璃字卡”或“按教程那组玻璃卡”时，读取 [玻璃字卡](references/玻璃字卡.md)：按 2026-10-17 最终示范使用极影毁片圆白字、左侧双条、每条独立单行并延长到口播片段结束，框与字一起移动；不套普通口播花字的寒蝉体阴影。

使用者 的字体、字重、描边、阴影、字号排布和跟踪返修，先读 [Looki图片对比学习的花字部分](references/visual-learning.md)。这是36组对比的制作判断；不把案例字号、增益与轨迹当成全局默认值。

## 使用者 原生文字阴影（2026-10-16 再次纠正）

- 用户已有的下拉／投影阴影保持原样；需要阴影时，直接启用 Text+ 文字内部负责阴影的原生着色元素（已确认样例为着色3）。只开启，不重设原生或用户手调的距离、偏移、方向、柔化、颜色及不透明度；不能套用固定小偏移把阴影拉近文字，也不另加 DropShadow 效果替代。
- 修改文字、位置、音效、标题控件或重建时，先读取并保留当前各着色元素的启用状态及阴影参数；“默认无阴影”不授权关闭已有阴影，“开启阴影”不授权重新设计阴影。不要根据元素名称或编号盲目覆盖外观。
- 写入前后核对：只要求开启时，仅相应 Enabled 值改变，其余阴影参数和用户排版保持不变。若之前已被错误改近且无可靠旧值，不能猜一个距离称为恢复；以用户确认的原生标题或手调版本为依据。


## 使用者 口播花字排版（2026-10-16 明确纠正）

- 以用户确认的本项目提供的花字演示参考和当前手调版本为视觉依据。口播强调字沿用示范的白字及原生阴影，不擅自改成橙色／主题色；B-roll中的指定黑字、镂空字或特殊配色按各自设计保留，不全片统一换色。即使旧示范含胸前或底部字，最新“口播文字始终在人物左侧或右侧”要求优先。
- 相机、摄像头、手机、电脑等产品图片、图标或矢量图，必须确认具体型号、版本和外观与当前产品一致；无法确认准确时一律不加，不拿通用示意图、近似机型或参考视频里的产品补位。此前由AI加入的错误图应撤下，不再追加另一张未经确认的替代图。
- 所有口播强调文字／花字放在人物左侧或右侧的可用空位，避开人物、M5 等产品图标、照片及其他展示内容；不能因为图标上方有空位，就把口播文字移到图标上面形成遮盖或挤压。
- 左侧已有 M5 图标时，“Mac Studio”放人物右侧，保留各自的空间。根据当前构图选择左右位置，不固定套坐标；照片标签可压图等通用规则不适用于这类口播花字。
- 用户手调的位置、大小与排布优先。重做、改音效、修标题控件或套样式前先读当前值并保留，不从旧计划恢复旧坐标；此次只修音效时不改花字位置。


## 制作方式优先规则（2026-10-16 用户明确指示）

默认用**剪辑页 → 特效库 → 工具箱 → 标题**中的 Text+／文本或指定标题预设。独立标题片段直接放主线，在剪辑页检查器修改。禁止把普通花字制作为装有 Fusion 文字节点的复合片段，不得以“可编辑”或程序暂不支持为理由改用自建 Fusion 合成。

Text+、Text、中文“文本”均按剪辑页标题理解。原生 Text+ 底层含文字工具，不等于进入 Fusion 搭节点；以独立标题片段、无需打开复合片段、可在剪辑页检查器改字为准。只有用户明确要求用 Fusion 时，才给点名的部分使用 Fusion；抠图、跟踪等效果需要 Fusion 时先问，不自行使用（见 AGENTS.md“禁止使用 Fusion”）。其他花字仍用标题。下文 Text+ 流程仅指特效库原生 Text+ 标题，不授权载体视频、复合片段或手搭文字节点链。

用户已说明自己审画面时，仅做内容、起止、写入及保存的必要确认后汇报；不自动抽帧、重开工程、连续播放复检或生成审片线。本文后面的完整验收和审片流程仅在用户要求时执行。

**默认静态（2026-10-16 用户明确纠正）**：没有明确动态要求，不添加任何关键帧或动画；花字加音效不自动包含弹出、缩放、位移、淡入。跟踪、逐字出现等仅在用户指定的段落保留，不能推广到其他花字。

**剪辑页控件必须真实可用**：脚本修改标题时，保留原生标题的模板信息，包括 Text+ 合成的 `CustomData.TEMPLATE_ID = "Text+"`。仅把片段类型或工具名改为 Text+ 不够；丢失模板信息会让剪辑页只显示标题栏，用户被迫进 Fusion。交付前在剪辑页实际选中一条，确认检查器显示文本编辑框、字体和字号，位置可在剪辑页设置中调整。其余同类标题只做模板信息与写入确认，不进行耗时抽帧审核。

## 标准用法（先读这一节）

1. 用户在精修时间线上打标记，或直接说“帮我加花字”。AI 读标记、字幕和截图，按 [风格手册](references/风格手册.md) 写计划。
2. 跟用户说清楚改哪个工程、哪条时间线、处理哪几处，用户同意后再 `build --apply`：花字以独立原生 Text+ 放在现有画面之上最低的一两条可用轨，跳过锁定、停用或被占用的轨；音效从 A3 起复用一两条音效轨，A2 留给 B-roll 原声。用户当次指定优先，计划可写 track 覆盖；没有可用轨才新建「花字/音效」命名轨。普通花字不做复合片段。
3. 交付前按文末 cleanup 演练清理本程序过程线，再交付主线位置与 `交付清单.md`，由用户审画面、节奏和试听。只有用户要求才另建审片线；审片线上不改字。
4. 有修改就直接点主线上的花字，在检查器改字、大小、位置，或由 AI 更新计划后以默认 auto 模式识别小修；整批新做才用 batch，手调保留。
5. 用户说“定稿”后入库，见文末“用完之后”。两人同时剪同一个工程时，用 `place` 合并（见下文）。

已知限制：空文字的原因还没查明，整批新做的 build 保留“保存→重开→文字不空”检查，小修不重开；对比标签在那段没说到对应词时，按画面节奏出现；抠像较慢（约 30 秒处理 1 秒画面），只给被挡的字做；两台 Mac 协作还没实测；现有 build 程序只支持特效库 Text+ 标题。用户要普通“文本”时使用剪辑页原生文本的可用操作，不用复合片段或自建 Fusion 合成代替。

共享工作台为本文件真实路径往上两级。新工作目录：项目存在 `3.视频素材/3.7AI素材` 或 `3.7 AI素材` 时，默认放其下 `花字音效/<批次>/`；批次默认计划文件名，可用 `--batch` 指定。没有该结构时保持 `<片名>_AI剪辑/花字音效/`。已有工作目录照常使用，不搬家；`--work-dir` 可明确指定，`--project-dir` 可帮助定位项目根目录。所有计划、过程、媒体和备份均放本片目录，不放能力仓库；已被工程引用的生成媒体不能当缓存删除。先由用户打开目标工程，不切换数据库或打开其他工程。写入一律用 `PYTHONUTF8=1` 的 DaVinciResolveScript 直连，不用 MCP 写操作，不自动渲染。

## 先读画面和标记，再写计划

```bash
python3 bin/fx.py snapshot --timeline '主时间线' --out '/本片/花字音效/snapshot.json'
python3 bin/fx.py markers --timeline '主时间线'
python3 bin/fx.py check '/本片/花字音效/snapshot.json'
python3 bin/fx.py still --timeline '主时间线' --frames 108100,108200 --out-dir '/本片/花字音效/静帧'
python3 bin/fx.py plan --validate '/本片/花字音效/plan.json'
```

每轮计划/build/小修均重新读取当前主线全部标记的名称和备注，不只循环旧 effects 台账；逐个和 source_marker 的 frame/name/note 对照。缺失、原文改变和未覆盖标记必须报告。交付清单逐个列“标记全文 → 实际花字/音效 → 轨道与起止范围”，未写入不得称完成。新做先看必要静帧，小修不自动导图；拿不准问用户，同类新样式先只做一个给用户看。不要把历史标记帧当作现有片段的位置，需结合当前片段、字幕或逐字时间。遇到已有空文字只报告，不猜原文、不补字。`markers` 标准输出为 JSON，标准错误为中文清单；检查失败退出码 2。静帧只导出当前时间线，核对时间码和文件并恢复播放头。

计划结构见 `engine/fx/testdata/plan_example.json`，样式/音效名取 `engine/config/fx_styles.json` 和 `sfx_favorites.json`。区间为绝对帧 `[start,end)`；`source_marker.frame` 为标记相对帧，name 和 note 保留当前原文。`layer` 表示逻辑层，同层不能重叠；实际轨道由最低可用轨规则分配。花字 `track`、每个 sound 的 `track` 可用已有正整数轨号或唯一轨道名覆盖；锁定、重叠或有后续片段时停止，不解锁用户轨。ready 计划每项须有主体框、`layout_approved=true` 和前置快照哈希；初次 build 的 `precondition_snapshot_sha256` 用 `engine.fx.ledger.digest(snapshot['timeline'])` 计算，快照变化须重新核对计划。

## 安全距离检查

`plan --validate`、build/place 演练及写入都检查文字外框。计划 `timeline` 填 `width` / `height`；离线校验可加 `--snapshot '/本片/花字音效/snapshot.json'` 读取分辨率与字幕轨。build 使用当前快照，并在保留手调后重新检查。

规则在 `engine/config/fx_styles.json` 的 `safety`：照片标签（photo_label）和大字（keyword）四边留短边的 3%，其他为 5%；避开整条字幕轨的保留区，位置读不到时统一保留底部 20%。每种样式的 `default_size` 取任务08相同字体/形态用户样本的稳定 Size 中位数；省略计划字号时采用默认值。字号下限为默认值的75%，动画最小值及片段缩放也须满足，不能用缩放绕过下限。普通 Text 按同字体 em 等大换算默认值及下限；未知字体先报错。

`anchor.subject_bbox=[左,下,右,上]` 是真实主体框。`subject_kind="person"` 允许外框与人物重叠不超过外框面积15%；手机、照片或未注明类型仍保留半个字高间距，不得压在主体上。只有用户明确批准的旧计划 `overlap_ok=true` 可豁免未注明类型主体的间距，照片标签默认 `overlap_ok=true`（显式false仍保留）；在 `subject_kind="photo"` 且 `overlap_ok=true` 时允许文字外框底部最多35%轻压照片顶部；仍避开另一张照片、手机、边缘、字幕区和字号下限。不要为消除报错虚构主体框。

同屏另有照片或手机时，可在 `anchor.avoid_bboxes` 填额外真实外框数组，统一保持半字高间距；移动建议同时避开这些外框，不能将标签从一张照片挪到另一张照片上。

违规会列出效果、原因、移动建议与可选做法，标为“需要用户决定”；不自动缩字。plan 校验不通过；build 默认跳过违规效果及其音效，其他效果照常，全部违规时不写入。操作记录和审片清单保留待决定项。只有用户接受不安全布局后才用 `--allow-unsafe` 强制写入；输出仍保留违规和强制记录。缺字体、字形或分辨率等无法估算的情况不会被该选项掩盖。任务已授权该选项时不重复确认。

外框根据本机 `~/Library/Fonts` 的字形边界/字宽、上下伸、对齐、片段 Pan/Tilt/Zoom、动画最大字号、阴影/描边计算。估算器支持 `style.engine` 为 `Text+`（默认，Size 比例）或 `Text`（1920 像素参考宽下的字号）；当前 build 仍只写 Text+，不能把普通 Text 的字号直接用于 Text+。当前写入使用居中；估算器的显式 `horizontal_align` / `vertical_align` 可描述普通 Text 的左/中/右、上/中/下/基线。未校准的 Text+ 对齐枚举会拒绝估算，不能猜。

## 口播起点与连续清单（10-16 使用者）

普通口播花字从对应口播首字出现帧开始，标记只提示附近位置。计划 `transcripts` 用“当前A1源完整路径 → 已有逐字JSON路径/对象”；不重新转写。效果 `speech.text` 可写对应原话，默认查花字文字；`speech.search_start/search_end` 限定找词区间（默认计划起止前后90帧）。按当前A1源区间映射；缺逐字时退回字幕并在清单注明“估算”；两者都找不到则停止，不能拿标记帧冒充。纯画面补充明确 `speech.mode="visual"`。已有花字手调起止优先保留，小修不重新自动排时。

多行累积清单给各行相同 `list_group`、样式、位置和可选 track，按每行首字排列；程序生成同一轨首尾相接的连续状态标题，内容为“第一行 → 前两行 → 全部三行”，新行才配本行音效。`list_line` 保存本行原文；未出现行用空行预留位置，整组按完整清单统一位置，避免切状态时旧行跳动。不得每行堆一条轨；同轨标题无论 layer 是否不同都不能重叠。

普通人物花字默认按真实人物框寻找旁边留白，再用遮罩核对；不自动居中盖脸或缩字。明确位置用 `anchor.placement="explicit"`，字幕替代或顶部居中分别用 `subtitle_replacement` / `top_center`。章节用 `kind="chapter"`，不用标点，改空格或换行。先输出可核对计划：

```bash
python3 bin/fx.py plan --validate '/本片/原计划.json' --snapshot '/本片/快照.json' --prepare-out '/本片/准备计划.json'
```

新批次 build 也会做上述准备，演练先核对起点、估算说明、轨道与真实布局后再执行。

## 小修与整批新做

小修是改已有几个花字的字、位置、时长或音量：一次备份，确认目标工程/主线、对象、位置和范围，再确认其他片段位置与启用状态零变化，保存后交用户审画面。默认 `--mode auto` 将已有至多5处、仅文字/位置/字号/时长/音量的计划变化识别为小修；也可明确 `--mode small`。不导图、不关闭重开、不做全工程属性比对、不建审片线。当前 SDK 没有已验证的非波纹修剪方法，遇起止变化先列目标与新范围，由执行 AI 在剪辑页定点修剪、读回并做一次位置确认，不回退为整批重建；此路径仍待实机验证。

只有实际失败、位置不明确或可能误改时定向排查；超过10分钟先简短向用户说明原因和缺口。整批新做用 `--mode batch`，保留一次备份与“保存→重开→文字不空”检查，不把参数通过说成用户认可。

## 用户明确要求 Fusion 时

默认禁止 Fusion，只有剪辑的人明确说要用 Fusion 时才按本节做；抠图、跟踪需要 Fusion 时先问。自动人物压字用独立的人物抠像轨（透明 ProRes），不是 Fusion，照常使用。先复制需要的片段范围，做成独立复合片段，在复合内制作，不在原片直接加。新建节点要显式设置 FlowView 位置、分开排布并清楚命名，检查没有重叠。只给用户点名的标签跟踪，同屏其他字不自动一起跟踪。普通花字仍用开头规定的剪辑页标题。

## build 自动人物压字

普通人物花字先执行旁边留白规则；真实遮罩有覆盖时继续移到零覆盖，挪不开停止，不回退盖脸。明确指定位置、照片等效果才沿用下述遮挡阈值。默认开启 `engine/config/fx_styles.json` 的 `matting.enabled`；最大遮挡比例 `matting.max_coverage` 默认20%。所有花字由程序先判断V1可见区间，再用 RVM 真实遮罩决定，build 演练只报告待计算，apply 才生成。人物覆盖0时不放抠像层，0到阈值时人物在字前；超过阈值则自动向远离人物的方向找最近安全位置，不缩字。找不到位置则保持原文字盖在人上，并在操作记录和审片清单注明。同屏有回退花字时，共享人物层避开其区间，防止其他花字的抠像层再次盖住回退文字。安全检查的矩形人物15%规则继续用于独立 plan 校验；自动 build 使用真实遮罩，仍执行边缘、字幕、照片、手机和字号规则。

读取V1源区间，遇上层可见视频/照片区间不抠；变速、未校准的旋转/透视/裁切/动态缩放不猜，记录为无抠像回退。独立环境 `~/.codex/tools/ai-edit-matting/` 由 setup_mac 自动准备，doctor 报缺项。透明 ProRes4444为时间线分辨率，保留原RGB并调整ZoomX/ZoomY及Pan/Tilt补偿输入缩放；Straight Alpha、Full Range、Input LUT/色彩空间和CopyGrades均读回。源路径/大小/修改时间、源区间、模型及输出版本/分辨率组成缓存键，缓存只放本片工作目录 `抠像/`。解码、推理、转码三阶段串行，不生成临时PNG；临时raw在程序私有临时目录用完即清理。

主线最高轨「人物抠像」位于原生花字之上，同时出现。重建只非波纹替换本程序认领且状态未动的层；用户移动、删除或改变可读属性时停止并保留现场。旧版 decompose-check 额外核对人物层仍在花字上方。审片底图副本停用内部人物层，在审片V2直接复制人物素材、变换和调色，避免重复合成；清单列出每项覆盖比例、移动与回退原因。无需用户手工抠像、导入或摆轨。

解码、推理、转码三阶段串行，一次仅一个ffmpeg进程；CPU推理、ffmpeg解码/编码及滤镜最多4线程，减少同机使用时的负担。

## 同意后制作，审核后重建

**先向用户说清改哪个工程、哪条主时间线、处理哪些标记，得到同意后才运行 `--apply`。** 已明确授权本次范围不用重复询问。所有写入命令都要求 `--project`、`--timeline`；默认仅演练，不写工程。

```bash
python3 bin/fx.py build --project '工程名' --timeline '主时间线' --plan '/本片/花字音效/plan.json' --work-dir '/本片/花字音效'
# 用户已同意该范围后：
python3 bin/fx.py build --project '工程名' --timeline '主时间线' --plan '/本片/花字音效/plan.json' --work-dir '/本片/花字音效' --apply
```

build 先检查音频轨、目标轨和操作记录，再备份主线 DRT。按最低一两条可用轨分配，按起点升序插入原生 Text+；音效集中复用 A3 起的一两条轨，均粉色标识。记录全部锁状态、入出点、播放头和标记，临时锁住目标轨以外的全部轨；写入前先查目标轨：插入点之后有任何片段就禁止 InsertFusionTitleIntoTimeline，换安全空轨；没有安全位置则停下报告。每插一个读回实际轨道、起止、样式，并确认其他片段位置零变化（小修也必做）。插入推动的标记用删除、按原字段和 customData 重加的方式恢复，逐项读回；结束或暂停都恢复用户原来的锁状态、入出点和播放头。用户自己锁的轨保持锁定。

换层时先只用锁轨尝试。Insert 返回空或落错轨时不重试，保存已完成的操作记录并以退出码 3 提示目标 V<n>（花字<k>）。**执行 AI 用电脑操作剪辑页菜单，把视频源目标设到提示的轨，然后运行同一条命令加 `--resume`（place 也支持）；不让用户手动做。** 必须保留原工程、时间线、计划、工作目录和安全选项；断点后计划或时间线变化则拒绝续做，已有花字不重放。

重建先排除所有用户手动制作或修改过的整个花字、音效及相关层，保留当前对象与节点，不删除重放；只有本操作记录认领、状态与最近 AI 写入基准完全一致且本轮明确授权修改的旧花字，才可按安全轨道与起点升序重放。没有可靠基准时保留现状。删除、移轨、启用状态变动需先确认。未认领片段全部保留；默认跳过有冲突或后续片段的轨，明确指定但不安全时停止，不覆盖、不删除。原口播、其他片段、轨道和标记须零变化；程序断言自有花字不是媒体池时间线或复合片段。音效专用轨含人声/原声/未知素材或自有音效被移到其他轨时，建花字前报错。
整批 build/place 会保存、关闭并重开**同一个工程**；小修只保存不重开。整批重开后，核对所有新花字文字、样式和位置。未通过时保留备份和失败现场，不自动重复运行；工具成功、参数通过、用户观看/试听认可分别汇报。

默认交付主线位置及清单。只有用户要求，整批 `build --apply --review` 才创建 `审片_<主线>_<MMDD-HHMM>`；小修不自动审片。也可独立运行：

```bash
python3 bin/fx.py review --project '工程名' --timeline '主时间线' --work-dir '/本片/花字音效' --pad 30 --merge-gap 30
```

审核点只取该工作目录的操作记录，同组花字算一处，已分解仍可审核；每处前后留30帧，相邻间隔小于30帧合并，段间留20帧。审片线及“无音效源”副本放在媒体池“花字音效/审片”，各段有青色提示标记，清单附原时间线中间静帧。V1仍嵌套原线画面；A1「人声与原声」嵌套无音效副本声音，副本关闭音效轨，并逐项停用混合轨中来自音效素材库的旧音效；A2「音效」仅直接放本程序实际存在、启用的音效素材，按原位置换算并读回源偏移、长度、音量。副本保留所有人声/原声参数，原时间线前后快照必须零变化。无法确认内部声音的嵌套音频、或单条A2放不下的重叠音效须先报告；不猜测或覆盖。同分钟重名不覆盖。颜色以原时间线为准，审片线只用来看。失败保留现场，先检查证据，不自动重复 build。

用户要修改时回到主线，直接点花字 Text+，在剪辑页检查器改字、大小、位置，也可打标记。审片线只用来看，不要在审片线上改。需要 AI 改时更新计划，优先走上述小修；不是每次都重建整批。用户手改对象整项退出自动重建，不以“逐字段保留后重建”代替保护。只有用户明确点名对象和修改内容时才局部修改指定字段，其余状态保持当前值。用户删除或新增花字需先确认计划，避免复活或丢失。用户移动、调音量、换文件或删除的音效不重放，按当前状态保留并报告。不要手动改操作记录来绕过检查。

## 两人同时剪：先做花字，后合并

另一人在剪主线时，先协调工程保存窗口；不能同时写同一条时间线。`build --defer-place` 用 `DuplicateTimeline` 把主线复制为 `<主线>_花字音效_MMDD`，在副本上按同一流程直接放 Text+、音效和人物层，主线片段保持不变；同名副本不覆盖。用户直接审副本，明确要求时才生成审片线；审完再 place 到主线。副本里的原生花字可以改，审片线只看。此模式仍会保存关闭重开工程，未经双方协调不要运行。跨 Mac 的协作锁与保存行为尚未实测，不能把本机测试当作双机通过。
负责人同意且主线空闲后，用相同工作目录执行：

```bash
python3 bin/fx.py place --project '工程名' --timeline '主时间线' --plan '/本片/花字音效/plan.json' --work-dir '/本片/花字音效'
python3 bin/fx.py place --project '工程名' --timeline '主时间线' --plan '/本片/花字音效/plan.json' --work-dir '/本片/花字音效' --apply
```

V1/A1 结构指纹一致才合并，且先排除主线和副本中所有用户手改对象。不能把副本手调对象按旧计划重建；只有用户明确要求把指定的手调定稿转入主线时，才按当前定稿状态转入，不重新设计。其余仅处理本轮授权且未被手改的 AI 对象；不把副本嵌套进主线。换层同样由 AI 设置源目标轨后 `place … --resume`。结构变了则不写入，逐个按源素材帧报告建议新位置、已删除内容或无法可靠定位的项，提示“需要先按新位置重建”。变速或源帧不唯一时不猜。计划自 build 后改过也须先重建。工作目录与指定工程/主线绑定；换目标需重新建计划，不能拿另一条线的片段 ID 去删除。

## 定稿入库与旧版分解核对

新版直接放主线，无需分解。用户明确定稿后运行：

```bash
python3 bin/fx.py learn --timeline '主时间线' --work-dir '/本片/花字音效' --case-root '<使用者指定的案例目录>' --name '案例名'
```

`decompose-check` **仅用于以前的嵌套结果**。旧版仍由用户在主线的粉色嵌套片段上右键“分解到原位”，AI 不替用户点击分解，然后：

```bash
python3 bin/fx.py decompose-check --project '工程名' --timeline '主时间线' --work-dir '/本片/花字音效'
```

decompose-check 只读工程，验证每个普通 Text+ 的非空文字、样式和起止，以及分解前其他片段/轨道/标记零变化；通过才在本地操作记录标“已分解”。之后 build/place 只读这些花字，不再管理。learn 仅在用户明确定稿后运行，以当前时间线为准，包含手做/手调内容；保留同名目录不覆盖。传入操作记录时按效果身份、位置、文字对照首次 AI 状态，统计原样保留、改过哪些字段、被删、用户新增；采纳率=(保留+改过)/AI 总数，有歧义不报比率。无操作记录则 `ai_vs_final=null`。

入库输出 case.json、summary.md、宽960成片/源图及一致性证据。源图为 V1 原素材，不含上层 B-roll 和调色；不可靠源帧逐条跳过并说明。失败案例保留 failure.json，不当作定稿。文字关系和弹出分类是规则推断，需复核。

花字细节看 [花字.md](references/花字.md)，音效看 [音效.md](references/音效.md)，定稿案例索引看 [风格手册.md](references/风格手册.md)。不自动改风格手册。

## 用完之后：反馈与迭代

1. **每次用完**：有用户手改、纠正、新偏好或卡住的地方，按 本项目的反馈记录约定 在 本次项目的已确认反馈 新建一条；没有就不写。只记录，不自己改规则。
2. **用户说“定稿”或“这版定了”**：直接 `learn` 入库到使用者配置的数据目录，用一句话告诉用户采纳率：AI 做的有多少原样保留、改过、删掉，用户新加了几个。在 [风格手册](references/风格手册.md) 的案例索引里加一行（只加索引，不改规则）。
3. **用户说“整理经验”或“整理花字”**：按 本次项目的已确认反馈 汇总 本次项目的已确认反馈，同时看案例库里最近的案例和采纳率，列出建议清单：改风格手册哪条、改哪个默认值、依据是哪几次。**用户勾选后才改**，按 AGENTS.md 占位、测试、存档，并记入 本次项目的已确认反馈。
4. **AI 先出初版（实验功能）**：攒够约 6 个案例，且连续两条采纳率都不低于 70% 时，提醒用户可以试试。做法：不看标记，按字幕、截图和风格手册写整片计划，其余流程不变；定稿后照样入库、算采纳率。

## 波形同步与交付整理（2026-10-16 用户明确纠正）

音效与文字的同步以真实波形的目标瞬态对齐文字实际出现帧，不能对齐素材左边界。素材可提前起；多尖峰先辨认承担同步的一下。用户要求逐帧对齐时，不套用默认提前1帧或只用静音检测当作验收；按 [音效.md](references/音效.md) 的波形核对执行。

最终交付时，AI 新建的过程、测试、备份时间线先导出到本片 AI 素材目录，核对有效嵌套依赖和独有修改后清理。保留用户原有时间线及有效依赖；不为此次修正再建过程线。

交付清理命令（默认演练，仍会导出工程外 DRT；只加 `--apply` 才删除）：

```bash
python3 bin/fx.py cleanup --project '工程名' --timeline '主时间线' --work-dir '/本片/花字音效'
python3 bin/fx.py cleanup --project '工程名' --timeline '主时间线' --work-dir '/本片/花字音效' --apply
```

只认 `AI时间线.json` 中本程序实际创建的UID，不按名称猜；旧过程线没有创建记录时报告保留。创建与完成时在 `时间线外部备份/` 留 DRT；清理再导出到 `时间线清理/`。当前快照和DRT内容均与程序完成基线一致、无独有修改、无保留时间线的视频或音频嵌套引用才可删；未知修改、未完成过程、有效依赖都保留并报告。过程线之间按父线先删、依赖后删，循环依赖停止；保留用户原有线。实机导出稳定性和删除接口尚待独立测试；导出差异宁可阻止删除。
