# 花字制作与审核

## 使用者 原生文字阴影（2026-10-16 再次纠正）

- 用户已有的下拉／投影阴影保持原样；需要阴影时，直接启用 Text+ 文字内部负责阴影的原生着色元素（已确认样例为着色3）。只开启，不重设原生或用户手调的距离、偏移、方向、柔化、颜色及不透明度；不能套用固定小偏移把阴影拉近文字，也不另加 DropShadow 效果替代。
- 修改文字、位置、音效、标题控件或重建时，先读取并保留当前各着色元素的启用状态及阴影参数；“默认无阴影”不授权关闭已有阴影，“开启阴影”不授权重新设计阴影。不要根据元素名称或编号盲目覆盖外观。
- 写入前后核对：只要求开启时，仅相应 Enabled 值改变，其余阴影参数和用户排版保持不变。若之前已被错误改近且无可靠旧值，不能猜一个距离称为恢复；以用户确认的原生标题或手调版本为依据。


## 使用者 口播花字排版（2026-10-16 明确纠正）

- 以用户确认的本项目提供的花字演示参考和当前手调版本为视觉依据。口播强调字沿用示范的白字及原生阴影，不擅自改成橙色／主题色；B-roll中的指定黑字、镂空字或特殊配色按各自设计保留，不全片统一换色。即使旧示范含胸前或底部字，最新“口播文字始终在人物左侧或右侧”要求优先。
- 相机、摄像头、手机、电脑等产品图片、图标或矢量图，必须确认具体型号、版本和外观与当前产品一致；无法确认准确时一律不加，不拿通用示意图、近似机型或参考视频里的产品补位。此前由AI加入的错误图应撤下，不再追加另一张未经确认的替代图。
- 所有口播强调文字／花字放在人物左侧或右侧的可用空位，避开人物、M5 等产品图标、照片及其他展示内容；不能因为图标上方有空位，就把口播文字移到图标上面形成遮盖或挤压。
- 左侧已有 M5 图标时，“Mac Studio”放人物右侧，保留各自的空间。根据当前构图选择左右位置，不固定套坐标；照片标签可压图等通用规则不适用于这类口播花字。
- 用户手调的位置、大小与排布优先。重做、改音效、修标题控件或套样式前先读当前值并保留，不从旧计划恢复旧坐标；此次只修音效时不改花字位置。


- 独立剪辑页原生标题直接放主线；在画面之上最低的一两条可用轨放字，跳过锁定、停用、冲突轨。用户当次指定优先，计划 track 可覆盖；没有可用轨才新建命名轨。插入点后同轨有任何片段时禁止原生 Insert，改用安全空轨或停止。按起点升序，每次核对其他片段位置零变化。
- 样式配置：white_bold 寒蝉端黑体 `ChillDuanSans / Black`；圆体 `????? Medium / Undefined` 对应“极影毁片圆.ttf”，不要误用 `????? / Medium`；spec 为 `AidianFengYaHeiChangTi / Regular`；trip 为 `Alimama ShuHeiTi / Bold`；outline 使用双描边。
- 默认静态，不添加关键帧；仅计划明确写 animation 时制作。对比标签也默认直接出现。阴影默认关闭；用户要求时启用字体原生着色3，保留自带参数，不用固定小偏移代替。需安全外框估算时先读取原生 Offset3/柔化值到计划 overrides。暂不支持 Center 跟踪自动写入，不能静默忽略；需要 Fusion 时按主 Skill 的独立复合片段规则制作，仅跟踪被指定标签。
- Center 坐标原点在左下，JSON 的点坐标须转整数键再给 SDK。片段 Pan/Tilt/Zoom 单独记录。comp 帧 = RenderStart + 时间线帧 - 片段起点；GlobalIn=RenderStart，GlobalOut=RenderStart+duration-1。片段 end 排他。嵌套源相对0开始，AppendToTimeline 的 endFrame 用花字时间线长度，主线 recordFrame 用主线起点；中文“时间线”和英文 Timeline 都识别。
- 普通人物花字先按真实人物框放旁边空处，遮罩有覆盖则移到零覆盖，挪不开停止；明确指定位置的效果才沿用独立plan人物框15%、自动build遮罩20%的遮挡规则。手机保持半字高间距；照片标签默认允许底部最多35%轻压照片顶部，仍避开别的照片及字幕。成组文字对称、居中、对齐基线。同时独立的规格可分别用 Text+；逐条累积的多行清单用同轨连续状态标题，保留前项、新行按口播出现，同轨不重叠。
- 操作记录逐 effect_id 保存片段ID及写入指纹；重建前按字段比对用户手调。不能把弹出首帧缩小误判为用户改字号；字号取曲线末端值，完整曲线另存。内部新加或删除花字、外部移动/缩放嵌套时停止确认计划，不覆盖。原有花字和其他轨道不搬动。

## 空文字的保存验证

2026-10-08 在本地测试工程做过六组、每组两例：仅 StyledText、文字+GlobalIn/Out、文字+Lock/StartUndo/EndUndo、全套输入、全套+Undo、写文字后切 Fusion 页。全部完成保存→关闭→重开，12例均保留文字。另做前插24帧波纹对照（24/150帧标题、仅文字/全套写入各两例）及保存前复制对照；也未重现空字。另在原线的多轨副本做8例仅文字/全套输入、24/150帧和前插24帧对照，全部保留；SDK实际插入V1，未复现历史A1的V15目标轨环境。

因此“只写 StyledText 必然导致重开空字”不成立；第0阶段那10例及用户旧工程空字的根因尚未查明，不能称已修复该历史故障。正式执行器采用 GetInputList 加载、StartUndo+Lock、写完整文字/字体/颜色/阴影/位置/GlobalInOut、按计划写入的BezierSpline、Unlock+EndUndo，并逐项读回。整批 build/place 保存、关闭并只重开同一个工程；小修不重开，定点写入与位置确认后交用户审画面。整批重开后，逐字/样式/位置核对；发现空字立即失败并保留现场。此验证是持久性验收措施，不是根因已查清的证据。

保存比较采用数值容差，不用精确哈希判定浮点数是否改变。原始快照全部保留；仅对未启用着色元素的零值 RGB/柔化控件，在重开后 SDK 读成 null 时视为同一未启用默认状态；启用控件和非零值变化仍报错。这是 SDK 加载状态的边界，原始差异会保留在证据中。

当前测试用 Resolve Studio 21.1.1.10、29.97fps；尚未实测另一台 Mac 或共享数据库。参数读回、静帧抽查不等于动画播放和用户审美验收。

## 普通 Text 标题实测（2026-10-09）

当前继续用 Text+，未增加 `title_engine` 选项。普通 Text 的离线 DRT 已能显示基础文字，但阴影尚未取得可靠写入及视觉核验方法，未满足全部关键属性通过才切换引擎的条件；不能把这个结论写成“DRT 完全不可用”。

- 指定本地测试工程中，中文界面用 `InsertTitleIntoTimeline('文本')` 成功，英文 `'Text'` 曾返回空。片段在 V1、108000–108150，`GetFusionCompCount()==0`；`GetProperty()` / `GetProperties()` 均为空字典，`dir()` 无专用标题文字或关键帧方法。
- 对文字、字体、字重、字号、颜色、阴影偏移/颜色/柔和度/不透明度、描边、位置及缩放的 60 种常见键，各用 `SetProperty` 和 `SetProperties` 测一次，120 次均返回 False；逐项读回、九组静帧与基线像素一致。因此这些属性不能依赖本次所测 SDK 接口设置。
- 从真实普通标题导出的 DRT 是 `Sm2TiGenerator / PrettyType=Rich`。用 `rich-title-encoder.js` 写 `EffectFiltersBA`，通过 `ImportTimelineFromFile` 导入：文字、字体、字重、字号、颜色可显示；位置存于 effect 48 的参数 17，两项大端 double 为归一化坐标。连续五个基础样式均导入、重新导出解码并看图通过。中心位置 (0.5,0.5) 会被 Resolve 省略为默认值，不应误判为空位置。字体名可读回不代表字体必有全部字形，Arial/Times New Roman 的中文仍可能字体回退。
- 阴影和描边：SDK 所测键无效；该编码器未提供对应参数，默认真实样本也没有这些参数；本轮 GUI 返回 `cgWindowNotFound`，无法补取手调样本。DRT 阴影四项和描边均未验证，不能声称可用于既有硬边阴影/双描边样式。弹出动画同样未取得可验证的普通标题关键帧方案；静态缩放键也返回 False，不把 DRT 动画未验证写成格式原理上不支持。
- Text+ 简洁性实测：`FX验收_1008` 的 V18/V19/V20 已分解，按操作记录的名称、轨道、起止和实际文字唯一对应 11 个花字，并扫描三条原独立花字线的 11 个标题。每个合成总工具数为 **3**：TextPlus、标准 MediaOut 输出、Size 的 BezierSpline 各 1；无表达式、额外效果节点或其他连接。不能报告成“总共只有 1 个工具”。


快照注意：非活动时间线的轨道启用状态可能全部读成 false；先激活目标时间线再读回比对，完成后恢复测试线。不能为消除读数差异而修改原线轨道。

## 安全外框与校准（2026-10-09）

- 坐标统一左下原点；`subject_bbox` 是主体真实外框，不是允许放字区域。照片各自有自己的框，不能把两张照片的空隙当作同一个主体。
- Text+ 的字体单位换像素：`Size × 画宽 × 0.8 ÷ (OS/2.sTypoAscender − sTypoDescender)`。从字形轮廓读上下伸及实际黑像素范围，从 hmtx 读前进宽；居中按前进宽对齐，不能把字形黑像素框直接硬居中。逐字体的基线偏移保存在 safety.font_calibration。
- 2880×2160 实测“拍照！”（.088）、“24毫米主摄”（.04750665）、“长焦”（.045），白字阈值127排除黑阴影，四边最大误差0.764像素。安全框另加阴影/描边及2像素余量；动画取关键帧和Bezier控制点包围范围，包含过冲。未校准字体额外留0.15em垂直余量，不把估算当成逐帧视觉验收。
- 普通 Text 的估算字号按 `字号 × 画宽 / 1920` 转成 em 像素；基于06任务已导出的3840×2160样式图核对。此处是外框估算支持，不代表普通 Text 阴影/动画写入已通过。
- 字幕轨读取所有字幕项（包括当前时间没有显示或被停用的项）。如快照提供归一化 `SubtitleBoundingBox` / `BoundingBox`，取整条轨的纵向并集并扩成全宽保留带；任意项位置读不到，合入默认底部20%。本地 Resolve 21.1 的字幕 GetProperty 为空，本次实际用了默认区，不冒充已读到字幕位置。
- 非居中语义对齐可供离线估算；Text+ 非默认枚举在本次探测中只读回参数变化、静帧未变，尚不能确认其视觉映射，因此不静默推定，不用于当前 build。字形缺失、未知字体、未知枚举报错。复杂排版/字体回退不能靠字宽推断通过。
- 默认字号见 fx_styles.json 的 default_size（相同字体/形态用户样本中位数），最低75%；照片标签/大字边缘3%，其他5%，字幕规则不变。普通Text默认字号按字体度量换算，不能直接使用Text+的Size数值。字号不足或放不下时不自动缩字：列为“需要用户决定”，build跳过这一项及其声音，其他继续。用户明确接受后可用 `--allow-unsafe` 强制；结构错误或未知外框仍失败。

## 自动人物抠像（2026-10-09）

独立RVM运行环境、透明ProRes4444、缓存和时间线分辨率变换补偿见主Skill。最高轨「人物抠像」独立于花字嵌套；重建认领和decompose-check均包含人物层。覆盖比例使用整个片段Alpha并集与最大文字外框，是保守估算，不是逐字形遮挡的精确比例。审片底图副本关闭内部人物轨，V2直接复制人物层，避免重复Alpha合成。

## 对比标签（用户 10-11 反馈）

左右照片/画面并排对比使用 `kind=compare_label`、样式 `compare_label`。先在固定对比区间找每个词的第一次出现：优先读取已有A-roll逐字结果，由 `engine.fx.compare.map_a1_words` 按A1片段源帧映射；没有逐字结果时，用字幕中字位置/字数在字幕区间内按比例估算，清单注明“估算”。不得借用对比区间之外的词。

对比区间内没说到该词：左标签在开始后3帧、右标签在约40%处出现，错峰至少15帧；清单明确“按画面节奏，不是口播对齐”。不移动照片、不改对比画面区间。每个标签出现后保留到对比结束，默认静态；计划明确要求弹出时，Size在0至3帧由80%到100%。每组按咻-起身 → UI弹出 → 清脆鼠标点击的连续顺序配音效（左右两个取前两项）。

白字、主题橙色 #FF6F00 底；只用同一Text+的着色元素2（ElementShape2=2底框、Level2=1整行），不加额外Fusion节点或表达式。底框延伸、颜色与透明度写入并读回，安全外框包含底框。`engine.fx.compare.schedule` 生成 `comparison` 中的对比区间、左右身份、词、逐字/字幕证据与找词方法；计划校验重新核对各词的起点、组内一致证据、音效及明确要求的弹出，不允许两个起点借用同一个词。过短的区间报告，不能假称对齐。
