# 使用者：Looki L1 图片对比学习（2026-10-16）

以下为匿名化的通用剪辑判断示例，不包含原始图片、项目路径或个人记录。

读取范围：配画面读“B-roll”；制作花字读“花字”；返修读“调整顺序”。当前用户指示及较新的明确纠正优先。普通标题、轨道分配、接口操作仍按对应子 Skill 执行。

## 花字：先确定字形，再确定体量和构图

| 场景 | 下一次如何做 | 本次依据 |
|---|---|---|
| 口播强调、短关键词 | 优先寒蝉端黑体（ChillDuanSans / Black），用字体本身的粗细形成体量；放人物肩膀附近的左右空处，避开脸、手、产品图标和字幕。 | 很多照片、保留记忆、回顾全天、AI眼镜 |
| 双侧并列 | 先提炼为含义准确的短词，保持单行、同字体、同字号，分别落在主体两侧；按剩余空间判断整体平衡，不机械镜像坐标。 | 上周某天／记不清楚、时间／事件 |
| 三项列举 | 同组字体、字重、字号与行距统一，按对应口播逐条出现，语义组结束共同消失。中间一行可作为整组居中参照。 | 保存／筛选／整理；几点睡／累不累／好好休息 |
| 功能说明、数字清单、轻提示 | 可采用用户手调的圆体（本次为极影毁片圆），用足够字号保持可读；不是看到 B-roll 就统一圆体。 | 工作与休息、随手拍摄／语音交互等列表 |
| 暗背景、需要强调的 B-roll 大字 | 大寒蝉白字也适用，靠字形和对比度突出，不必加阴影。 | 时间／事件、生活漫画 |
| 指定“刷／唰”张力效果 | 参考用户指定的斜体标题预设、并列或纵向叠列、透视关系，配刷声音效。只有点名段落使用对应动态。 | AI时代／自媒体时代／先关心自己 |

### 字重、描边、阴影分别处理

- **字重**决定笔画本身粗细。先选正确字体与 Black／Bold 等真实字重，再调字号；不要用加粗描边、复制多层文字或阴影代替字体字重。用户的“笔触”在此指字形外观，不另做手绘素材。
- **描边／镂空**属于单独的造型选择。保留用户已有轮廓、填充和着色层；不因为要“更突出”就把所有字加粗边，或把镂空字改实心。当前画面需要何种造型，以用户示范为依据。
- **阴影**解决背景分离。新做第一遍默认不带，用户要求再开；本轮“口播寒蝉加阴影”“单加一行字默认加阴影”的明确要求在相应范围生效；“这一组不要阴影”和暗底无阴影是明确例外。不能由此推导全片永远都加或都不加。
- 已有阴影保持原样。需要开启时使用标题内部已确认负责阴影的原生着色元素（本次样例为着色3），只改需要的启用状态，保留原生／手调的偏移、距离、方向、柔化、颜色和不透明度。不另套固定参数或 DropShadow。
- 本次部分圆体的内部字体名显示 `????? Medium / Undefined`，实际文件为 `极影毁片圆.ttf`。先核实字体文件与实际字形，不能只凭名称显示异常判为缺字或换成别的字体。

### 字号与位置怎么调

先看最终画幅、主体和文字占比，再调字体、字号、单行／行数、位置与行距。字体尽量大而醒目，同时留出主体、画面边缘及字幕的空间；用户主动缩小时按构图回调，不追求填满空位。

“很多照片”曾由 Size 0.067 调至约 0.1063；“时间／事件”最终约 0.1299；圆体清单约 0.064。这说明**不同用途需要不同体量**，不能把这些值当默认字号，也不能跨字体、分辨率和标题缩放直接复制。对照最终画面判断，用户已有位置、字号和阴影优先保留。

文字提炼只减表达负担，不改事实。本次“20TB起步”等是用户修订的内容，不授权把未来口播的“几十TB”自行改成具体数字。

## 出现、结束与声音

- 花字紧扣对应词，尤其名词的首字。例如“上周”应在“上”开始时出现；逐条列表分别对齐各条口播，不统一贴整句起点。
- 音效可以先于花字，按**有效波形及实际听到的重音／瞬态**对齐花字首次可见的时刻。用户说的“音效显了一半再出字”是听感示范，不是将所有音效文件机械取一半。文件前导空白、双击中的两次声响应分别判断。
- 结束以相关口播语义组和实际画面交接为准。A-roll 接下一段 B-roll 时，相关花字顶到交接处结束，既不提前留几帧空隙，也不越过所属段落。底层 A-roll 未裁开不代表花字该一直延长；B-roll 花字按该画面的出现／结束或对应口播结束判断。用户已手调的边界优先。
- 常用鼠标、UI、刷声等按内容轮换，不整片重复一个音效。改音效时保留已经确认的文字排布。
- 示例曾统一降低至约 -10 dB，这是片段增益操作，**不等于 LUFS 归一化或听感等响**。不得用它覆盖较新的共享默认 -5 dB；新任务按当前要求、源音效和人声判断，保留用户混音。

## 普通标题与跟踪分别制作

普通花字直接使用剪辑页原生 Text+／文本或指定标题预设，独立标题片段，默认静态；“加音效”不自动代表弹出、缩放、位移或淡入。剪辑页检查器必须实际能改文本、字体和字号，只有“Text+／在Fusion中打开”标题栏不算交付。

默认禁止 Fusion；只有剪辑的人明确要求用 Fusion 做跟踪等效果时，才复制所需片段范围，新建独立复合片段后制作；保留原片。节点按处理顺序分开摆放、连线清楚、命名可理解，各段效果独立管理。

本次仅 **Looki L1 名称跟踪产品，32克保持静态**。以前脸为位置参照，保留主体与文字的距离，平滑抖动、限制突跳，不把噪声和每次小晃动都传给文字。不要加额外旋转或摆动来表现“跟踪”。轨迹必须来自当前镜头，不复用其他素材轨迹。

## B-roll：从句子要证明的内容选镜头

先写清“观众需要看见什么，才能理解或相信这句话”，再选择**实际动作 → 被记录的内容 → 结果／证据**。问题主要是剪辑思路，不应简单归因于人物素材过滤；自己工作的实拍同样能作 B-roll。照片、截图、录屏、漫画和视频都可用，先看清画面实际内容。

| 口播目的 | 初稿 → 用户调整 | 可复用判断 |
|---|---|---|
| 我做自媒体／实际拍摄 | 设备合照／手机图库 → 自己账号主页／拿相机拍摄 | 身份用本人证据，行动用实际过程。 |
| 记录产品与品牌 | 地图录屏 → 历史项目拍摄画面 | 镜头必须支持该句，不能仅因同属 App／产品素材就替代。 |
| 再找某个片段 | 手机图库 → Finder 找文件操作 | 让观众看见“找”的动作；窗口、背景和光标组织为可读信息。 |
| 工作现场被记录 | 佩戴产品实拍 → 实际夜间外拍 | 从“戴着设备”推进到“设备记录了什么”。初稿本身已有实拍，不能误记为只有 App。 |
| 向助手提问／三个建议 | 泛助手界面／口播 → 实际问题／可读的三条建议 | 展示真实输入和回答内容，给阅读所需时间。 |
| 连续十几天的记录 | 手机内小漫画 → 多日期漫画大图 | 用多张记录建立数量和时间跨度；快切服务信息，不固定套帧数。 |
| 晚上工作／收尾时间 | 原始录屏／生活漫画 → AI原话划重点／报告与大标题 | 证据放大，关键词明确，减少无关界面。 |
| 生活里的关心 | 整屏漫画 → 人物与报告同时可见 | 情绪由本人表达，内容由证据说明，二者可以并存。 |
| 给生活留空隙／具体生活背景 | 用餐或手机漫画 → 本人工作状态／对应真实记录 | 同一漫画不反复代替所有生活语义。 |
| 运动相机／AI眼镜用途 | Pocket画面／口播 → Action实际使用／眼镜佩戴互动 | 设备类别准确，优先实际用途。 |
| 结尾对观众说话 | 漫画覆盖 → 回到面对观众的口播 | 需要关系和态度时主动留露脸。 |

覆盖率不能替代叙事判断，也不能直接当作“看不到人的比例”。不把本片覆盖率、约21帧漫画切换或任意最短镜头时长变成所有项目的目标；读报告需要停留，展示数量可以快切。

## 调整顺序：保留手调，只改问题字段

1. 先确认当前工程与主线，读最新标记**全文和备注**，逐条对应现有文字、音效、轨道与起止。不能只执行旧计划，漏掉新增的“作息混乱”“生活里的小事”等标记。
2. 按内容准确 → 选镜头／字体 → 字号与排版 → 描边／阴影 → 起止与声音的顺序定位问题；用户只点名一个方面时只动相应字段。读取当前值，不用旧计划覆盖手调。
3. 同类新样式先确定一个代表例，再按每处实际构图调整。用户已授权范围就继续完成，不反复要求批准已确认的动作。
4. 核对分三层：参数确认只能证明写入；画面能证明构图；试听能证明音效对齐与听感。按本次任务做必要验证，用户已说明自己审画面时不自动批量抽帧、另建审片线或反复重开。
5. 报错按位置隔离原因。某个嵌套镜头曾是嵌套底层素材尾帧失效；不能见 Fusion 报错就认定文字节点有问题，也不能把本片尾帧保持修法推广到所有片段。
