# 中文口播剪辑工作规范

## 手工定稿优先

“只要是我改过的素材都不要再改了。”所有工程都以用户当前手改版为最终素材，按 [a-roll 入口的保护规则](../SKILL.md#用户手工定稿保护所有工程所有-skill2026-10-17) 排除整个手改对象；不能用旧审核状态或新映射重新交付覆盖。只有用户明确点名该对象的再次修改才操作指定内容。

本规范适用于本共享能力处理的口播初剪、重录选择、气口修复和达芬奇时间线整理。用户本次指定的节奏、版本和保留内容优先。不要把本次某一个切点的帧数、静音阈值或某台 Mac 的媒体 ID 套到其他素材。

## 工程准备与确认

新项目在剪辑前先汇报要做的步骤与大致耗时，把本项目尚未明确的问题集中询问：工程叫什么、如何导入素材文件夹、LUT 规则及套用范围、时间线要什么格式。用户已给出的答案直接复述确认，不再问一遍；新项目不能自动继承上一项目的画幅；LUT 及套用范围按当前项目确认。现有项目每次更改前也先汇报具体改动；用户要求先看方案时等其指令，否则按已授权范围继续。不增加用户未要求的渲染、优化媒体、审核网页等步骤。

以下为可配置的项目准备规范：

1. **名称。** 从用户给的素材路径向上找到 NAS 项目根文件夹，以其 `XXXXXX_项目名称` 为工程名候选并询问确认，例如 `示例产品开箱`，不用 `C3849` 等原片名或 `_mcp_…` 作为可见工程名。文案、达芬奇工程与素材项目文件夹应同名；发现不一致提醒用户，以 NAS 文件夹名为最终版，不擅自改 Notion 文案或 NAS 文件夹。
2. **主媒体夹与 LUT。** 按用户指定的项目素材目录导入并保留子层级，复用现有素材，保护手改，不重复导入。LUT 类型与范围先确认；只对需要的画面应用，读回 Input LUT 核对，不给纯音频套 LUT，不叠加已经存在的 LUT。脚本使用 `SetClipProperty('Input LUT', 名称)` 时写显示名称，不带 `.cube` 扩展名。
3. **只改时间线格式。** 每个新项目先问选 16:9、4:3 还是 3:4；帧率或裁切方式另有要求时按本项目确认。16:9 默认 3840×2160；4:3 在目标时间线设置中取消“使用项目设置”，设 2880×2160；3:4 同样只在目标时间线设 2160×2880、正方形像素并启用竖屏分辨率。本引擎完整自动流程仅支持恒定 29.97 fps，分辨率不匹配时缩放原图填满并裁切超出部分，不擅自改变既有时间线帧率。MCP 写入使用目标 `Timeline.SetSetting`（先 `useCustomSettings=1`），不使用 `Project.SetSetting` 或项目设置接口改画幅。写入前后读回项目与目标时间线：项目原格式不变，目标线的自定义开关、宽高、像素比例和裁切方式符合选择；保留用户已经设好的值。

现有 `deliver` 的自动建项程序 `engine/src/setup_new_resolve.py` 仅在未绑定已有工程且没有时间线时按原片改 **项目** 分辨率；绑定已有工程时不改项目格式，不能用于代替上述准备。需要走该交付程序时，先通过 MCP 创建/打开已确认名称的工程、按要求建立时间线并完成文件夹导入；在本项目 `审核/project_runtime.json` 中用 `project` 绑定工程名、`existing_project_only: true` 限定已有工程、`media_pool_item_id` 绑定已导入原片。它新生成的主线仍需单独通过 MCP 按用户选择设置并保存、重开、读回；不能只核验准备线，也不能为了让旧程序通过而改项目格式。这次准备规范不扩展剪辑引擎的多文件或帧率支持范围。

完成名称、导入/LUT 和时间线确认后再进入下面的剪辑流程。

## 操作顺序

1. **确定段落、句子和有效录制版本。** 阅读整份原始逐字稿，按完整意思划分句段，结合前后录制顺序识别重录。重复录制优先保留最后一遍完整、正确的表达；后面的残句、口误或不完整版本不能仅因为更晚就入选。优先使用同一次完整表达，避免从不同遍次拼字或拼半句。多条原片合成一条口播时先向用户确认录制顺序，再逐条转写；各文件已有识别结果校验后复用，不重复付费识别，不用片名猜测顺序。
2. **先做连贯初剪。** 按句段保留连续原始音画，删除确定的废话、错误版本和现场提示。逐字时间用于定位和防吞字，不用于逐词压缩停顿。保留一句话里的正常短换气及必要字音边缘，选句后继续第 4 步检查多余气口。相邻区间来自同一素材且源帧连续时合并，移除无意义刀口；不要留下多个极短气口碎片。短片段若含独有字音，不可只因时长短就删除。
3. **核对内容完整性。** 对照源素材与原稿，检查重复句、漏句、错选遍次和吞字，尤其检查句首、句尾、英文词及重录接缝。恢复独有内容；不能为了节奏缩短完整表达。用户确认的修正保留在可追溯审核状态中，不重写原始识别稿。
4. **精剪多余气口。** 每次口播初剪都检查整片句内短语间停顿、句首句尾和重录接缝，不只处理用户标出的点；具体做法见下节。用实际音频、波形与逐帧核对确定可删区间，数清每处可删帧数。语音对齐和低能量检测只提供候选；不能只凭标点、统一时长、固定帧数或一个静音阈值下刀。两端保留完整字音，不能从气口机械向两边扩大。边界不确定时保留并如实记录待核对处。
5. **连续播放验收并整理主线。** 检查声音自然、字音完整、动作衔接、漏删长停顿与多余碎片。已有满意的连续版本在原基础上精修，不重回逐字紧剪。移除 Codex 为本次审核添加的标记，保留用户标记。每个视频项目最终只留一条完整主时间线，用户要求保留多条除外；三个独立视频仍是三个项目，各自一条，不拼成一个视频。

## 气口精修与手改学习

- **初剪后补查句内停顿。** ASR（语音识别）可能把多个短语归为一句，`natural_pause_mode: "sentence"` 只是保守初剪基线。继续检查“写进去｜让它按要求来做”“打好标记｜再给参考图”等动作承接、并列说明和转折前后的停顿，以及句尾说完后残留的等待；正常换气、强调、情绪和段落转换所需的停顿仍保留。不以整片必须缩短多少秒作为目标。
- **逐处决定删哪里、留多少。** 连同前后完整短语核对原声、波形及画面，确定上一字尾音和下一字起音后再裁。切得生硬时可局部补回字音边缘、缩小删除区间；不把用户某次补回的帧数变成全片统一留白。时间戳把停顿归进尾字时，不能只因区间与“了”等 token 重叠就认定删了这个字，也不能只凭低能量判定它没有发音；未核实的保留并标注待听审。
- **把精修写进实际映射。** 在项目 `审核/气口精修.json` 记录前后原话、源帧区间 `[a,b)`、实际增删帧数、切点依据和听审状态。对于尚未被用户手改的 AI 初剪，将核实的裁剪合并到最新审核状态的 `resolve_frame_cuts[].source_frames`，保留已有裁剪及用户选择；复用 `review_v2_server.persist_state(previous,current)` 的备份和冲突检查，再用 `review_build.build_full` 重建统一映射，重新 `proofread` 后校对并 `corrections --done`。该字段能裁句内间隙和首尾，但禁止整词被静默删光；若保护校验报错，先核对字音与本项目对齐边界，不绕过校验。已有审核状态不重新 `review`，不删除状态文件重来。
- **手改版按源素材对比。** 比较同一源文件的保留区间，分别统计句内切除、片段首尾修边、局部补回及整句换遍次；时间线整体前移和片段数量增加不等于换了内容，差异区间数量不等于操作次数。对齐回退处结合原声核实，不仅凭 token 中点推断删词。用户已经精修的主线按其当前源帧继续维护，不能用旧审核状态重新交付覆盖；只要求复盘时不改时间线。


## 气口怎样才算真正剪掉

- 确定停顿的源帧左闭右开区间 `[a,b)`，记录实际删除 `b-a` 帧、前后原话和边界依据。当前支持的帧率为 `30000/1001`；不要把时码最后一段当毫秒。
- 对齐字界只用于限定候选安全范围。若上一字音结束为 `L` 秒、下一字音开始为 `R` 秒，完整位于其间的帧范围最多是 `[ceil(L*fps), floor(R*fps))`；仍需核对实际音频，两者不一致时不能照公式强剪。
- 检查拟删区间不进入任何保留字的真实发音范围，尤其防止削掉尾音、弱辅音及下一字起音。保留 token ID 不变不等于没有吞字，部分音节也可能被错误裁掉。程序的字界检查与实际音频核对须同时满足。
- 在气口两端确定切点，删除中间对应的联动视频和音频，并波纹闭合，后续内容一起前移；位于片段尾部的气口可直接收短尾部并闭合。打标记、切一刀、切出小片段而没有删除，均不算完成。字幕应采用同一实际删后映射。
- 用 Resolve 读回核对：源帧区间已消失；音画删同样的帧数且保持链接；后续位置确实前移；总时长相应减少；没有空隙、残留气口小片段或无意义的源连续刀口。然后播放接缝，确认没有吞字或异常动作跳变。分别记录程序核验与听审结果，不能把结构读回说成已完成听审。

## 保留状态与时间线收尾

- 修改现有项目之前先保存并读回当前时间线，对照最近冻结映射记录用户的手工删选；不能用旧审核状态覆盖用户已改的源帧范围。
- 新项目以句内连续模式生成保守初剪（`natural_pause_mode: "sentence"`）：每个 ASR 句段内先保留词连续，句与句之间紧剪，不加额外帧；语义删除和重录所在间隙照常删除。紧挨的短词叠用（如“一直卡一直卡”“忙着忙着”）默认保留；拿不准的重复保留并在 finish 摘要中列给 AI 语义复核，明显停顿后重说仍按口误候选处理。随后仍须执行上节气口精修，不能把“句内连续”当成最终不用检查气口。旧项目没有该字段，行为不变。精细控制可用 `natural_pause_ranges`（合并指定源帧范围内的间隙）和 `resolve_frame_cuts`（在合并后精确扣除源帧，不能整个删掉审核保留的字）；按本片记录设置，不复制旧片区间。
- `deliver` 自动只在主文件夹留一条最新含字幕主线，本程序生成的旧版移入“历史版本”文件夹；用户自建、改名或用途不明的时间线不移动、不删除。整理后核对主线的音画源偏移、链接、字幕和时长；后续修改继续维护这条主线。
- 用户只要求在达芬奇查看时，不额外制作审核入口或面向用户的交付包。必要的内部状态与备份仍可保存。只有用户要求网页修改时才提供对应入口。不自动渲染，不为复盘或气口修改重复调用已有 ASR。

## 完成标准

句子完整、重录选对、字音不丢、多余停顿实际删除并闭合、画面衔接自然、字幕跟随实际音画、每项目一条完整主线、Codex 标记已清除。未能确认的字界或听感要具体说明，不能用“已经打点”“已经切开”代替剪辑完成。
