# AI 口播剪辑

**禁止使用 Fusion**：除非剪辑的人明确要求，否则不用 Fusion；需要 Fusion 才能做的效果先问。详见 AGENTS.md。

## 用户手工定稿保护（所有工程、所有 Skill，2026-10-17）

**用户原话：“只要是我改过的素材都不要再改了。”用户手动制作或修改后的版本就是最终素材。**

- 适用于所有工程与所有制作 Skill，包括 A-roll、B-roll、字幕、花字、音效、图片、窗口、Fusion 节点及其参数。手动改过的整个素材／片段从批量修改、统一样式、重建、替换、清理和重新交付中排除，不能只保留几个改过的字段再重建它。
- 每次写入前以当前工程为准，对照上次 AI 写入记录辨认手改，并按片段 ID、源素材和当前范围记录保护清单。原本由 AI 创建也不代表可以继续接管；没有可靠基准或不能确定是否手改时，保留现状，不覆盖。
- 手工参考只供只读学习；不能修改参考本身，也不能用旧计划、默认参数或统一模板把手改版恢复成 AI 旧版。用户删除、替换、停用或拆掉的内容不得自动补回。
- 只有用户明确点名该对象并要求再次修改时，才调整其点名的内容，其他部分仍保留。“全片统一”“全部重做”“按这个模板”本身不授权覆盖手工定稿素材。
- 工具若不能排除受保护对象，就改用只处理已授权目标的局部方式；做不到则跳过该项，不能先整批覆盖再补回。写后核对保护对象没有变化；发现误改只撤销本轮造成的变化，不拿旧快照覆盖用户新改动。

用户要求剪口播、修气口、删重复、修吞字或跳切时使用，不必用户点名。剪辑判断标准见 [口播剪辑工作规范](references/editing-workflow.md)，实际剪辑前必须读取；仅转写时不执行剪辑步骤。

## 准备

1. NAS 共享工作台是本 Skill 文件夹（`a-roll`，各 Mac 上是指向 NAS 的符号链接）真实路径往上两级，通常是 `<仓库根目录>`；读根目录 `AGENTS.md`（硬性边界），运行 `python3 bin/doctor.py`（JSON；`--summary` 为中文清单，`missing` 列出缺项与下一步）。未接入或有缺项的 Mac 运行 `bash bin/setup_mac.sh`。若 `shared_code_being_modified` 不为空，说明另一人正在修改共享程序：把其中内容告诉用户，等用户确认后再开始识别或交付。
2. 转写看 `video_transcription_ready` 与 `shared_doubao_key_api_verified`；完整剪辑还需 `alignment_dependencies_ready`、`subtitle_dependencies_ready`。对齐环境默认 `~/.codex/tools/ai-edit-align/bin/python`，其他位置用 `doctor.py --align-python <Python>` 检查，`init`/`align` 传同一参数或设 `AI_EDIT_ALIGN_PYTHON`。MCP 文件存在不等于已连上达芬奇。
3. 新项目从原片路径向上找到含 `3.视频素材` 的项目根；若有 `3.视频素材/3.7AI素材`（也识别 `3.7 AI素材`），默认放入其 `A-roll_AI/<片名>_AI剪辑/`，否则放在原片旁 `<片名>_AI剪辑/`；已有目录照常使用、不搬家，用户指定目录优先，不能放入共享工作台。

## 新项目先确认

接到新的达芬奇剪辑项目，先按 [工程准备与确认](references/editing-workflow.md#工程准备与确认) 汇报必要步骤与大致耗时，确认 **工程名、素材文件夹导入方式及 LUT 规则、时间线格式** 后再建项、导入和剪辑。用户已明确本项目的答案时复述即可，不重复发问；每个新项目重新确认，不沿用上一项目的画幅；LUT 按使用者本项目确认的规则执行。修改现有项目也先汇报本次改动，保护用户手动调整。

工程名按用户确认的项目目录确定；素材保留原有层级。LUT 及套用范围由本项目确认，不预设个人 LUT。新建 16:9 时间线默认 3840×2160，4:3 可用 2880×2160，3:4 可用 2160×2880；仅修改目标时间线，保留已有项目设置。详见工程准备规范。

## 完整剪辑：`python3 bin/edit_project.py <动作> --project-dir <项目目录>`

标准顺序：**prepare → 写选择 → finish → 气口精修与映射重建 → 字幕校对（corrections … --done，必做）→ serve 打开网页给用户审核 → 用户点“保存到达芬奇”（或 deliver）**。用户只想在达芬奇里看时，校对并 `--done` 后直接 deliver，不开网页。

审核一旦生成（`审核/review_v2_state.json` 存在）就不再重新生成：之后对选择的修改让用户在网页里改；真要从头重选，用一个新的项目文件夹（可复用原片旁已有识别结果，不重复计费）。绝不删除审核状态文件来“重来”。

1. **prepare** `--video <原片>`：记录原片显示分辨率（含手机旋转）；检查恒定 29.97 fps、单音轨和对齐依赖后才调用付费识别（豆包极速版 `volc.bigasr.auc_turbo`，单次 ≤2 小时、≤100 MB），然后在后台开始声学对齐（日志 `审核/align.log`）。项目里已有识别结果会校验后复用，不重复计费；另一台 Mac 生成的结果也可复用（按声音比对）。已初始化的项目不会被覆盖。
2. **选择**（对齐在后台进行时同时做）：通读 `审核/sentence_units.json`，判断重录、残句、现场交流；保留独有信息，重录取最后一遍完整正确的表达，不确定就保留。有文案时据此判断有效版本，但说法不同处保留现场原话。写 `审核/review_decisions.json`，示例：

   ```json
   {"reviewer": "Codex：单次全文语义审核", "limitations": ["接缝听感需用户听审"],
    "cuts": [{"unit_id": 0, "char_start": 0, "char_end": 12, "text": "我用了很多年的苹果手机，", "reason": "重录：保留后一遍完整表达", "replacement_ids": [4]}]}
   ```

   `unit_id` 是 `sentence_units.json` 里的 `id`；`char_start`/`char_end` 是该句 `text` 里从 0 开始、不含结尾的字符位置，`text` 必须与这段原文一字不差；删整句就从 0 到整句长度；`replacement_ids` 是保留的那一遍的 `unit_id`（没有就 `[]`）；什么都不删时 `cuts` 为 `[]`。`reviewer` 如实写审核方式，一次判断不得写成两次。不改写正文。
3. **finish 与气口精修**（有文案加 `--script <文案.txt>`，Word/飞书先转纯文本）：等待对齐完成，生成可逆初剪（默认句内不剪、句间紧剪；对不准的字回退到豆包原始字词时间，被拆开的整词如“五百”合并为整词；选区写错会报出第几条、怎么改），做文案对照，生成字幕校对稿，输出中文摘要。**finish 只生成保守初剪，不代表气口已精修。** 随后按 [气口精修与手改学习](references/editing-workflow.md#气口精修与手改学习) 检查整片句内短语间停顿、句首句尾及重录接缝，实际删除已核实的多余气口，并重建统一音画/字幕映射，再进行第 4 步；拿不准的保留并具体列出。字幕校对完成前不打开网页（避免用户看到未校对的字幕）。
4. **字幕校对（导入达芬奇前必须完成）**：finish 已生成 `审核/字幕校对.json`（每句保留下来的字幕、字编号；有文案时附 `script_candidates`），重新生成用 `proofread`。逐句通读并按其中 `rules` 改正：有文案时数字、型号、品牌、专有名词按文案写法（如“X五百”→“X500”、“叉三百”→“X300”）；没有文案时按上下文判断原意改正同音字、错字、的/得；识别得和实际说的完全不一样时按说话人原意改写；现场换了说法、临场加话以实际说的为准，不套用文案。校对稿里每句的 `words` 是 `[字编号, 原字(, 已改写法)]`；一个字编号可能是整词（如“五百”），`before` 必须写这个整词。改动存成 `审核/字幕纠错.json`，示例：

   ```json
   [{"id": "u4c21", "before": "五百", "after": "500", "reason": "型号按文案写法"},
    {"id": "u30c16", "before": "脚", "after": "焦", "reason": "同音识别错字：长焦"},
    {"ids": ["u3c1", "u3c2"], "before": "Mac Studio", "after": "Mac Studio", "reason": "跨词整体纠错，保留英文空格"}]
   ```

   连续多字用 `ids` 按原顺序列出同一句相邻编号，`before` 写覆盖的原文，`after` 写完整替换（含所需空格），不要拆改英文 token 来拼空格。范围整体显示并保留所有字编号与时间；只删选范围内部分字后须撤销该范围纠错并重新校对。after 不能为空；撤销以前的某处改正写 `{"id": "…", "remove": true}`。用 `corrections --file 审核/字幕纠错.json --done` 写入并标记校对完成；没有要改的也要用 `corrections --done` 标记。校对完成后再 `serve` 打开网页给用户。用户之后在网页里恢复了被删的话，新出现的字幕需要重新 `proofread` 并校对、再 `--done`，否则不能导入。新项目未标记前，交付和网页“保存到达芬奇”都会被拒绝。审核网页开着也可直接写入；网页提示状态已更新时刷新即可。用户纠正过的人名、品牌、型号，校对完顺手追加到仓库根目录 `词库.txt` 并提交（仅在用户授权后更新自己的本地词库，勿提交个人术语）。拿不准的改动和 `possibly_missing` 中的句子告诉用户。用户也可在网页选中一个字点“改字幕”。
5. **网页**：`serve` 打开（已运行则复用），`status` 查看，`stop` 停止；共享程序更新后服务空闲时自动重启。同一项目只能运行一个服务。
6. **deliver**（或用户在网页点“保存到达芬奇”）：经 MCP 打开/新建用户已确认名称的工程，建线前核对原片与目标帧率；默认帧率不一致且无法独立指定时，在建线前中文停止，不改项目设置。DRT 导入前后核对项目宽高/帧率，变化则恢复并记录，恢复失败停止。按上述工程准备规范绑定原素材与时间线格式（只修改目标时间线画幅，保持已有项目设置），生成含字幕主线 `<片名>_主线_<月日-时分>_<编号>`，保存、关闭重开、读回核对音画偏移、链接、字幕和分辨率。保存前若主文件夹里本程序生成的旧主线被用户在达芬奇改过（片段、字幕或加了轨道），中文报错停止并提示先改名；调色、音量、缩放等不改变片段和字幕的修改查不出来，所以开始精修前就应让用户把主线改名；主文件夹只留最新主线，旧版移入“历史版本”（不删除，用户自建或改名的不动）。交付文件发布到 `交付/`，`审核/latest_delivery.json` 指向最新版。MCP 单次 90 秒超时；未通过核验不得报告成功。不渲染。

片子定稿后可运行 `clean` 列出能重新生成的文件（对齐音频、预览缓存、旧日志与较早备份；交付包始终保留）及大小；把清单告诉用户，得到同意后才加 `--yes` 删除。`交付/` 根目录只放最新的 SRT/DRT/DRP，旧版本在 `交付/历史/`。单步动作 `init`、`align`、`review`、`script` 仍可单独使用（排查问题时）。失败时 `edit_project.py` 输出“出错了 / 下一步 / 原始信息 / 完整日志”（`审核/错误日志.txt`），向用户转述中文部分。项目 `审核/project_runtime.json` 设 `existing_project_only: true` 时只打开已有同名工程，找不到即停止。

配 B-roll 不在本 Skill：用户要配 B-roll、换备选、开 B-roll 原声或标露脸句时，读 `skills/b-roll/SKILL.md`。

## 仅转写

`python3 bin/transcribe_video.py --video <原片> --work-dir <本机新目录>`：本机提音、直传豆包，结果只存本机（`转写预览.txt`、`doubao_turbo.json`、`transcription_manifest.json`、`timings.json`）。多音轨须先试听，用 `--audio-stream N`（从 0 开始）明确选轨。中断后用同一视频、同一目录重跑。默认抽样校验原片并完整校验提音，`--full-source-check` 才完整哈希原片。时间为 `-1/-1` 的空格项不能用作切点。旧目录缺校验信息时保留原数据请用户核对（换新目录会再计费）。提示“上次请求没有完整结果”时，用户确认核对过用量才加 `--retry-uncertain`，不要自动重试。

## 验收与汇报

- 预览、SRT、达芬奇时间线使用同一保留区间；原片在操作中改变即停止。
- 区分程序核验（结构读回）与用户听审；说明待听的接缝、拿不准的纠错和漏念句。
- 涉及删除/恢复的界面测试只在隔离状态里做；性能数据区分提音、API 往返、对齐、预览和交付，不拿缓存复用速度冒充新调用。
- 更换 Key 用 `bin/doubao_credentials.py` 的本机页面，只接受豆包语音新版控制台的 Key。

## 用完记经验

任务结束时，有用户手改、纠正、新偏好或卡住的地方，按 本项目的反馈记录约定 在 本次项目的已确认反馈 新建一条；没有就不写。用户要求复盘气口时，按工作规范比较源帧及实际音频，区分删停顿、修字音边缘与换台词。未收到明确的 Skill 修改要求时只记录；用户明确要求采纳时按根目录 AGENTS.md 修改、验证并存档。
